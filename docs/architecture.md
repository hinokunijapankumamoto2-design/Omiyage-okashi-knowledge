## 核となる設計思想

### 1. ローカルファーストのデータ主権
- すべての知識は `.md` ファイルとして企業内ストレージに保持
- 検索・編集・バックアップは既存のファイル管理ツールで完結
- Claude API への送信は「質問時の必要範囲のみ」

### 2. フラットで透明な構造
- 独自のデータベースやバイナリ形式を使わない
- `.md` ファイルなので、10年後も任意のエディタで読める
- AIに依存せずとも、人間だけで情報を引き出せる

### 3. AIが進化しても資産は残る
- LLMが変わっても、ナレッジそのものは独立して存続
- 将来別のAIツールへ乗り換え可能（ベンダーロックイン回避）

## コンポーネント詳細

### Obsidian Vault
- ユーザーが定義する任意のディレクトリ
- `.obsidian/` はObsidian設定（リポジトリには含めない）
- `.md` ファイル群が実体

### Claude Code + スキル
- ユーザー階層 `~/.claude/skills/` に配置
- `SKILL.md` にAIへの指示が記述される
- どのディレクトリからでも呼び出し可能

### 設定ファイル（2つ）
1. `~/.claude/knowledge-config.json` — Vaultパス、言語等
2. `~/.claude/settings.json` — Stop Hook を含むCC全体設定

## データフロー

### 投入フロー
```
ユーザー → Obsidian / エクスプローラ → raw/*.md
```

### 整理フロー
```
Claude Code起動 → /second-brain → 
  raw/ 全読み込み → LLMで分類 → wiki/*.md 生成
```

### 質問フロー
```
ユーザー質問 → wiki/ 全検索（grep/read） → 
  LLMで回答合成 → 回答表示 & wiki/ に追記
```

### 学習フロー（自動）
```
セッション終了 → Stop Hook発火 → 
  会話レビュー → 条件該当時のみ mistakes.md 追記 → 
  次回セッション開始時に自動読込
```

## 拡張ポイント（コンサルメニュー）

以下は本リポジトリ基本形には含まず、カスタマイズで提供：

### 1. 基幹システム連携
- POSデータCSVを定期的に `raw/` へ流し込む ETL
- ERPの商品マスタとの双方向同期

### 2. 社内MCPサーバー
- 社内DBへのAIクエリをMCP経由で提供
- 権限制御・監査ログ付き

### 3. 独自スキル開発
- 業界固有ロジックを持つ専用スキル
- 例: `/competitor-analysis`、`/packaging-review`

### 4. CI/CD自動化
- GitHub Actionsで月次ヘルスチェックを自動実行
- 異常検知時にSlack/Teams通知

### 5. マルチユーザー対応
- Obsidian Syncまたは独自同期層
- 編集コンフリクト解決ルール

## パフォーマンス特性

| 規模 | ファイル数 | 初回コンパイル所要 | 質問応答 |
|---|---|---|---|
| 小 | ~100 | 5-15分 | 数秒 |
| 中 | ~1,000 | 30-60分 | 10-30秒 |
| 大 | ~10,000 | 要チューニング | 要インデックス設計 |

大規模運用時はRAG層の追加を推奨（要カスタマイズ）。
