# パイプライン契約（project.json）

全 8 工程が読み書きする唯一のマニフェスト。定義は `src/types.ts`（zod スキーマ）にある。
読み込み時に必ず検証されるので、手で編集して壊れた場合はその場でエラーになる。

## トップレベル

| フィールド | 型 | 書く工程 | 説明 |
|---|---|---|---|
| `id` | string | new | プロジェクト識別子。ディレクトリ名になる |
| `title` | string | new | 題名 |
| `brief` | string | new | 企画の一次入力。ユーザーの指示そのもの |
| `spec` | VideoSpec | new | 解像度・fps・目標尺 |
| `plan` | Plan \| null | 1 企画 | 企画の確定内容 |
| `shots` | Shot[] | 2 台本 | **全工程の作業単位** |
| `assets` | Asset[] | 3〜8 | 生成物の台帳 |
| `steps` | Record<StepName, StepState> | 全工程 | 進捗 |
| `agentTask` | AgentTask \| null | agent 層 | Claude への未処理の作業依頼 |

## Shot — 全工程の作業単位

工程2 がこれを作り、以降の工程がそれぞれの成果物を紐づけていく。

| フィールド | 使う工程 | 説明 |
|---|---|---|
| `id` / `index` | 全工程 | `index` が再生順序を決める |
| `description` | — | 人間可読の内容説明 |
| `narration` | 6 字幕 | ナレーション原稿 |
| `caption` | 4 モーション / 6 字幕 / 7 合成 | 画面に焼く文字。空なら `narration` を使う |
| `durationInFrames` | 2 台本 / 6 / 7 / 8 | **合計が目標尺と一致すること**（誤差 1.5 秒でエラー） |
| `imagePrompt` | 3 素材生成 | 空なら工程3 の対象外 |
| `motionPrompt` | 4 モーション | 空なら工程4 の対象外 |
| `captureSpec` | 5 実写編集 | null なら実写を使わないショット |
| `assetIds` | 7 合成 | このショットに紐づく素材 |

## Asset — 生成物の台帳

`path` は `projects/<id>/` からの**相対パス**。絶対パスを入れると Remotion の
`staticFile()` 解決が壊れる。

`kind` が合成時のレイヤー割り当てを決める。

| kind | 出力元 | 合成時の扱い |
|---|---|---|
| `image` | 工程3（codex + GPT Image 2） | base（優先度3） |
| `motion` | 工程4（HyperFrames / Kling） | Kling 由来は base（優先度2）、HyperFrames 由来は overlay |
| `footage` | 工程5（video-use） | base（優先度1・最優先） |
| `subtitle` | 工程6 | 最上位レイヤー |
| `audio` / `design` / `video` | — | 音声・Figma 素材・最終出力 |

base の選択は `footage > motion > image` の順。実写があれば必ず実写が優先される。

## AgentTask — Claude への作業依頼

agent 層のステップが停止するときに書き出す。

| フィールド | 説明 |
|---|---|
| `step` | どの工程で止まったか |
| `tool` | 呼ぶべき MCP ツール名 |
| `instruction` | 作業指示。Claude はこれを読んで実行する |
| `requests[]` | ショットごとのパラメータ雛形 |

Claude は作業を終えたら `agentTask` を `null` に戻す。戻さないと再開時に同じ依頼が残り続ける。

## StepState

`status` は 4 状態。

- `pending` — 未実行
- `awaiting-agent` — Claude の作業待ち（`agentTask` とセット）
- `done` — 完了。`run` 時にスキップされる（`--force` で再実行できる）
- `failed` — 失敗。`note` に理由が入る

## 手で編集するとき

`project.json` を直接書き換えるのは正規の運用である（agent 層の writeback がそれ）。
ただし次の 2 点を守ること。

1. `durationInFrames` を変えたら、合計が目標尺と一致しているか確認する
2. `assets[]` に足したら、対応ショットの `assetIds` にも足す — 片方だけだと合成から漏れる
