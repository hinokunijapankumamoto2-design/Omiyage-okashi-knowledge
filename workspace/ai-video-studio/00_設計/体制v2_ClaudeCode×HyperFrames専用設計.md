# 体制 v2 設計書 — Claude Code × HyperFrames 専用スタジオ

参照記事「動画編集ツール不要｜Claude Code×HyperFramesでバズ動画を量産する方法」を解読し、
当スタジオを **Claude Code × HyperFrames だけ**の体制に再設計する。

---

## 1. 記事の解読 — 本質は3つ

長文だが、構造的な発明は次の3点に集約される。

### ①「動画 = テキストファイル」化

動画を HTML1本として定義し、ヘッドレス Chrome + FFmpeg が決定論的に MP4 化する。
これにより動画が **コードと同じ資産**になる: git で管理でき、差分レビューでき、
「先週の動画の色だけ変えて再書き出し」がテキスト編集で終わる。
LLM が最も大量に学習した言語（HTML）で書くため、エージェントの母国語作業になる。

### ② FRAME.md — ブランドの「動き方」を資産化

テンプレ臭の正体は技術不足ではなく**ブランド情報の不在**。
色・フォント・トーン（DESIGN.md）に**動きの言語**（登場・退場・転換・緩急）を加えた
FRAME.md をプロジェクトに置くだけで、以降の全動画がブランドの制服を着て出てくる。
1回の仕込みが全出力に効く、完全な資産型の投資。

### ③ 修正一文ループ — 価値は「違和感の言語化」に移動

「枠を外して、今話している単語は青に」——専門用語ゼロの一文で修正が通り、
再検証・再レンダリングまでエージェントが完結させる。
編集ソフトの操作スキルは陳腐化し、**違和感を言語化する目**が残る価値になる。
運用則: 1指示1テーマ、返ってきたら次、のリズムが最速。

## 2. 当スタジオへの適用 — 何が変わるか

### 2-1. Remotion の引退（合成・最終出力も HyperFrames へ）

現行 v1 は「シーン=HyperFrames → 連結=Remotion」の2段構え。v2 はこれを1本化する。

**技術的裏付け（hyperframes-core コントラクトで確認済み）:**
- 1つの composition に複数クリップを `data-start` / `data-track-index` で時間配置できる
- サブコンポジション（`<template>` + `data-composition-src`）でシーンを部品化できる
- `<video>` / `<audio>` は framework 管理で任意の深さに置ける
  → フォトベース mp4 も BGM/SE の wav も composition 内に直接載る
- 決定論レンダリング（クロック・乱数・ネットワーク禁止）は既存の作り方と同方針

**v2 の最終出力構造:**

```
projects/<id>/
├── FRAME.md               ← ブランドの動き方（スタジオ共通版を継承）
├── index.html             ← 動画全体 = 1つの composition（12秒・360f）
│    ├─ track 0: <video> フォトベース/実写（b1〜b5 を data-start で配置）
│    ├─ track 1: サブコンポジション（ずんちゃ丸・ストロー・記号）
│    ├─ track 2: 字幕・テロップ・コピーカード
│    └─ <audio>: BGM / SE（gen_audio.py の wav）
├── compositions/          ← シーン部品（現 scenes/ の後継）
└── assets/                ← 写真・音声・書き出し
```

利点:
1. **Remotion のカンパニーライセンス問題が消える**（前回指摘のコスト・法務リスク解消）
2. ツールが1つになり、修正一文ループが動画全体に効く（現行はシーン単位で分断）
3. `npx hyperframes preview` で**全体**をタイムライン付きでプレビューできる
4. ffmpeg 事前合成も不要になる（透過は composition 内のレイヤー重ねで完結）

移行は次の新規プロジェクトから。v1 資産（SVG・オーバーレイ・音声スクリプト）は
そのまま流用できる（HTML/wav なので）。

### 2-2. パイプライン8工程の再割り当て

| 工程 | v1 | v2 |
|---|---|---|
| 企画・台本 | Claude | Claude（BRIEF.md / STORYBOARD.md 形式に統一。公式スキルの書式を採用） |
| 素材生成 | codex / Kling | 変更なし（必要時のみ） |
| モーション | HyperFrames 単発シーン | composition のサブコンポジション群 |
| 実写編集 | video-use | 変更なし（実写素材の前処理として存続） |
| 字幕 | SRT + Remotion焼込 | composition の字幕トラック（HTML なので和文が絶対に崩れない） |
| 合成 | Remotion + ffmpeg事前合成 | **廃止**（composition 内で完結） |
| 最終出力 | Remotion render | `npx hyperframes render` |
| 音 | numpy 合成 + ffmpeg mux | numpy 合成 → composition 内 `<audio>` |

### 2-3. 導入済みスキルの活用

このリポジトリには公式スキル群が導入済み（hyperframes / -core / -animation /
-creative / -keyframes / -cli / -registry / media-use）。v2 の作業はルーター
`/hyperframes` から入り、複雑な合成判断は各スキルの手順書に従う。
検証は `npx hyperframes check`（lint / runtime / layout / motion / contrast の5ゲート）を
レンダリング前の必須関門にする。

## 3. FRAME.md — ずんだ茶寮版を作成済み

記事の第4章を実行し、スタジオ共通の `FRAME.md` を作成した（実物は別ファイル）。
出典主義（記事の抽出プロンプトの思想）に従い、全項目に出典を付した:
パレットはずんちゃ丸参照シートとポスター実物、トーンはペルソナ正本、
動きの言語は v1 制作で実証済みのイージング値から採録した。

## 4. 5レシピの当スタジオ翻訳

|---|---|---|

| ⑤pr-to-video | 直接は使わないが、**この体制ごと法人提案する**という記事の核心を採用（下記） |

### レシピ⑤の本質 = このスタジオ自体が提案商品

記事の結論「編集作業ではなく、動画が量産され続る仕組みを売る」は、
当リポジトリ（土産菓子B2B）の文脈にそのまま重なる。菓匠三全への提案は:

- 完成動画（12秒v1）= デモ
- FRAME.md + キャラクター正本 + シナリオテンプレート = 納品する「仕組み」
- 修正一文ループの実演 = 提案の決定打（その場で直して見せる）
- コスト構造: 生成API課金ゼロ・ライセンス障害ゼロ（Remotion引退により）

## 5. 運用規則（記事の運用術を成文化）

1. **修正は1指示1テーマ。** 詰め込まない。返ってきたら次
2. **専門用語で指示しない。** 見たままの違和感と欲しい状態を書く（発注者側の規律でもある）
3. **たたき台を最速で出す。** 完璧主義は初稿には適用しない。本領は直しのループにある
4. **check 5ゲート通過までレンダリングしない**
5. **FRAME.md にない見た目の判断が発生したら、その場で FRAME.md に追記する**（資産に還元）

## 6. 実写切り貼りの限界（記事の線引きを継承）

実写素材の細かいカット編集は引き続き HyperFrames の土俵外。
当スタジオでは video-use（工程5）が担い、仕上がった実写クリップを
composition の `<video>` トラックに載せる分業を維持する。
