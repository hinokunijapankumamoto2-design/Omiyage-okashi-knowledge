# セットアップ

## 1. 依存のインストール

```bash
cd workspace/ai-video-studio
npm install
npm run studio -- doctor      # 何が足りないか一覧で出る
```

`doctor` は script 層の依存だけを検証する。MCP とスキルは Claude 本体が持つものなので、
この CLI からは確認できない（下の「3. MCP / スキル」を参照）。

## 2. script 層の依存

| 依存 | 用途 | 導入 |
|---|---|---|
| Node.js 22+ | 実行環境 | 導入済み |
| codex CLI | 工程3（GPT Image 2） | `npm i -g @openai/codex` |
| OpenAI 認証 | codex の画像生成 | `codex login` または `OPENAI_API_KEY` |
| ffmpeg | 工程5（video-use） | `ffmpeg-static` を依存に含めてあるため追加作業は不要 |
| HyperFrames | 工程4 | `npm install` に含まれる |
| Remotion | 工程7・8 | `npm install` に含まれる |
| ELEVENLABS_API_KEY | 工程5 の単語レベル ASR | [elevenlabs.io](https://elevenlabs.io/app/settings/api-keys) で取得 |

### ffmpeg について

apt 権限が無い環境（このリポジトリの開発コンテナを含む）ではシステムに ffmpeg を入れられない。
そのため npm の `ffmpeg-static` に同梱されたバイナリを使う構成にしてある。

`src/adapters/ffmpeg.ts` の `envWithFfmpeg()` が `PATH` の先頭にそのディレクトリを足すので、
PATH 上の `ffmpeg` を呼ぶ video-use の Python ヘルパーもそのまま動く。

システムに ffmpeg がある環境ではそちらが優先される。明示指定したい場合は `FFMPEG_PATH` を設定する。

## 3. MCP / スキル

### Kling MCP（工程4）

未接続の場合、Claude の接続設定から `https://kling.ai/app/mcp` を追加する。

**未接続でも動く。** 接続済みの higgsfield MCP が `kling3_0` / `kling3_0_turbo` を提供しているため、
`mcp__higgsfield__generate_video` に `model: "kling3_0_turbo"` を渡せば同じ Kling モデルに到達できる。
どちらを使うかは `src/adapters/mcp-bridge.ts` の `TOOL_IDS` に定義してある。

### Figma MCP（工程1）

接続済み。デザイントーンの参照元として `get_design_context` を引く。
`project.plan.figmaFileKey` にファイルキーを入れておくと工程1 が自動で参照する。

### video-use スキル（工程5）

Claude Code のスキルとして登録が必要。

```bash
git clone https://github.com/browser-use/video-use ~/Developer/video-use
ln -sfn ~/Developer/video-use ~/.claude/skills/video-use
cd ~/Developer/video-use && uv sync
```

## 4. 動作確認

```bash
npm run studio -- new demo --title "デモ" --brief "商品紹介の縦動画" --duration 15
npm run studio -- run demo
```

工程1 は agent 層なので、ここで停止して Claude への作業依頼が表示される。
それが正しい挙動である（exit code 2）。

```bash
npm run studio -- status demo   # どこまで進んだか確認
```
