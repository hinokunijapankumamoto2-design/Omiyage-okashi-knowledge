# 工程担当者

8 工程それぞれの担当と、その工程で守るべき判断基準。
実装は `src/steps/` に、接続先は `src/adapters/` にある。

---

## 1. 企画プロデューサー — `plan`（agent 層）

**担当**: Claude + Figma MCP

brief から concept / targetAudience / keyMessage / tone を確定する。
Figma ファイルが指定されていれば `get_design_context` でカラーとトーンを引き、`tone` に反映する。

判断基準: keyMessage は 1 つに絞る。複数のメッセージを詰めた動画は何も伝わらない。

## 2. 台本ライター — `script`（agent 層）

**担当**: Claude

企画をショット列に割る。ここで決まる `shots[]` が以降すべての工程の作業単位になるため、
**このスタジオで最も影響範囲の広い工程**である。

判断基準: `durationInFrames` の合計を目標尺に一致させる（誤差 1.5 秒でエラー）。
各ショットに `imagePrompt` / `motionPrompt` / `captureSpec` のどれを持たせるかで、
以降どの工程が動くかが決まる。

## 3. アートディレクター — `image`（script 層）

**担当**: codex exec + GPT Image 2

`imagePrompt` を持つショットの静止画を生成する。企画の `tone` が全画像に共通の画風として渡るので、
ショットごとにバラバラの絵柄になることを防いでいる。

判断基準: 生成済みの画像は再生成しない（冪等）。作り直したいときは該当ファイルを消す。

## 4. モーションデザイナー — `motion`（両層）

**担当**: HyperFrames（script 層） / Kling（agent 層）

静止画があるショットは Kling で動かし、無いショットは HyperFrames で HTML から作る。

判断基準: 再現性が要るもの（テキストアニメ、図解、ロワーサード）は必ず HyperFrames に寄せる。
Kling は生成のたびに絵が変わるため、修正を繰り返す要素には向かない。

## 5. 実写ディレクター — `capture`（agent 層）

**担当**: video-use

`captureSpec` を持つショットの実写素材を編集する。フィラー語除去、カラーグレード、
単語レベル ASR に基づくカット。

判断基準: video-use の Hard Rules は正しさの規定であって好みではない。特に
「カットを単語境界にスナップ」「全カット境界に 30ms のオーディオフェード」
「セグメント抽出 → ロスレス concat」の 3 つは省略しない。
**字幕はここでは焼かない**（工程6・7 の担当）。

## 6. 字幕エディター — `subtitle`（script 層）

**担当**: スタジオ内製

出力タイムライン基準でマスター SRT を生成する。各キューの時刻は
「ショット内の相対時刻 + そのショットの累積オフセット」で計算する。

判断基準: `caption` が空なら `narration` を使う。両方空のショットは字幕を出さない。

## 7. コンポジター — `compose`（script 層）

**担当**: Remotion

レイヤーを確定して `timeline.json` を書く。順序は下から base → overlay → 字幕で固定。

判断基準: **素材が 1 つでも欠けていたら止める。** 欠けたまま進むと、
壊れた動画がレンダリング完了として出てしまい、発見が最後になる。

## 8. レンダリングマネージャー — `render`（script 層）

**担当**: Remotion

`out/final.mp4` を H.264 で書き出す。工程7 が素材の実在を検証済みなので、
ここで失敗するのは環境要因だけになるよう設計してある。
