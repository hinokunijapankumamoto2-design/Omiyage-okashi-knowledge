# 運用ガイド（営業担当向け）

エンジニアでなくても、商談前の準備と公開がこの手順だけでできることを目的とした文書。
技術的な詳細は `README.md`、提案文の正本は `docs/構築指示書.md` を参照。

## 1. 商談前チェックリスト

- [ ] 提案者情報（社名・担当・メール・電話）が画面に表示されている（赤字【要記入】が消えている）
- [ ] 閲覧キーを案件用に変更した（初期値のまま使わない）
- [ ] デモチャートに「※ダミーデータ」注記が表示されている
- [ ] 可能なら、ダミーデータをN.Y.C.SANDの実際のSNS言及（手動収集でよい）に差し替えた
- [ ] 期限表記（2026年6月30日）が商談日に対して矛盾していない ← **期限切れのまま見せるのが最悪のパターン**
- [ ] スマホでも一度表示確認した

## 2. よくある差し替え作業

すべて `src/config.ts` か `src/data/demo.ts` の編集で完結する。
編集後は開発担当に「ビルドして反映して」と依頼するか、Claude Code に以下のように指示する。

| やりたいこと | Claude Code への指示例 |
|---|---|
| 担当者情報を入れる | 「SENDERを 会社名○○／部署○○／氏名○○／メール○○／電話○○ に更新してビルドして」 |
| 閲覧キーを変える | 「ACCESS_KEYを ○○○○ に変更してビルドして」 |
| 期限を更新する | 「§11と追従バーの締切日を○月○日に変更して。指示書の正本も同時に更新して」 |
| 実データに差し替える | 「demo.tsの週次推移を次の数値に差し替えて。注記は『直近の実言及に基づく速報値』に変更して: …」 |
| 別の顧客向けに複製する | 「顧客名を○○に置換した別ブランチを作って。本文の顧客固有箇所を一覧にして確認させて」 |

> 価格・無償条件・限定枠の数字を変えるときは、必ず営業責任者の承認を先に取ること。

## 3. URLの渡し方

- 渡す形式: `https://＜デプロイ先URL＞/?key=＜閲覧キー＞`
- キー付きURLはメール本文に直接書いてよいが、**SNSや共有資料には載せない**
- 案件が終わったら（受注・失注とも）キーを変更して旧URLを無効化する
- 先方の社内転送は止められない前提で考える。本当に見せたくない情報は載せない

## 4. PDFが欲しいとき

ブラウザで対象ページを開き「印刷 → PDFに保存」。追従バーは自動で消え、稟議用の紙面になる。
正式な提案書はWord版（`docs/提案書_正本_Word版.docx`）が正本。Webは補助。

## 5. トラブル時

| 症状 | 原因と対処 |
|---|---|
| 「閲覧用URLをお持ちの方のみ…」と出る | URLに `?key=` が付いていない、またはキー不一致。正しいURLを再送 |
| 赤字【要記入】が出ている | SENDER未記入。§2の手順で更新 |
| グラフが表示されない | ブラウザ更新で直らなければ開発担当へ。商談中ならPDF版に切り替えて続行 |
| 先方から「データは本物か」と聞かれた | ダミーの場合は正直に「レポート形式のイメージです」と答える。誤魔化すと失注より悪い結果になる |
