# 東京玉子本舗様向け 提案マイクロサイト

B2B提案書「SNS需要シグナル分析サービス」を1ページ縦スクロールのWebアプリにしたもの。
用途は **商談時のデモ表示** と **送付後の補助資料**。一般公開を目的としたサイトではない。

> ⚠️ 顧客名入りの営業機密を含む。公開リポジトリにpushしないこと。

## ドキュメント構成

| ファイル | 役割 | 読む人 |
|---|---|---|
| `README.md` | セットアップ・デプロイ手順（本書） | 開発担当 |
| `CLAUDE.md` | Claude Code用の恒常ルール | Claude Code |

| `docs/運用ガイド.md` | 商談前の差し替え・公開手順 | 営業担当（非エンジニア可） |

## 初回構築（このリポジトリにまだ src/ がない場合）

プロジェクトルートで `claude` を起動し、次の1行を貼り付ける:

```
docs/構築指示書.md を読み、構築計画を提示して私の承認を得てから実装を開始して。
実装完了後は /pre-deploy を実行し、合否表を見せて。
```

計画段階で指示書の読み漏れを検出するため、承認前に実装を始めさせないこと。

## 技術構成

Vite + React + TypeScript + Tailwind CSS + recharts。静的SPA・1ページ。バックエンドなし。

## セットアップ

```bash
npm install
npm run dev        # http://localhost:5173/?key=＜閲覧キー＞ で確認
```

閲覧キーをURLに付けないと本文は表示されない（仕様）。キーは `src/config.ts` の `ACCESS_KEY`。

## ビルドとデプロイ

```bash
npm run build      # dist/ に静的ファイルを出力
```

`dist/` を Vercel / Netlify / Cloudflare Pages のいずれかに配置。

**デプロイ前チェック（必須）:**

1. `src/config.ts` の `SENDER` がすべて埋まっている（画面に赤字【要記入】が出ない）
2. `ACCESS_KEY` を初期値から変更済み
3. リポジトリ／プロジェクトの公開設定が **Private**
4. 可能なら Cloudflare Access 等でBasic認証相当を追加（閲覧キーは簡易ゲートにすぎない）

## ディレクトリ構成

```
src/
├── config.ts          # ACCESS_KEY / SENDER（差し替えはここだけ）
├── data/demo.ts       # デモチャート用ダミーデータ
├── components/        # セクション・チャート・CTAバー等
└── App.tsx
docs/
├── 構築指示書.md       # 提案書本文の正本
└── 運用ガイド.md       # 営業担当向け手順
```

## 編集時の注意

- 提案書本文（§1〜§11）の文言は `docs/構築指示書.md` が正本。アプリ側だけ直さない
- デモチャートの「※ダミーデータ」注記は削除禁止
- 価格・期限・無償条件の変更は営業責任者の確認を経てから
