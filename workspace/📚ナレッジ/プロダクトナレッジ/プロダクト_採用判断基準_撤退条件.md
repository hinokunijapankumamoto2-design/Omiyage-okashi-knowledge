# プロダクトナレッジ: 採用/不採用判断基準・撤退条件

> **用途**: 商品企画・販路・案件・支援の「採用/不採用」を明文化する判断基準集
> **作成日**: 2026-04-21
> **核心**: 「何を採るか」と同じくらい重要なのが「何を見送るか」「どこでやめるか」

---

## 0. このナレッジの意図

多くの企業が失敗するのは、**悪い案件を採るから** ではない。
**止められない案件を続けるから** である。

本ナレッジは、以下の4領域で判断基準と撤退条件を明文化する:
1. **商品企画の採用/不採用**（企画会議用）
2. **販路・チャネルの採用/不採用**（営業判断用）
3. **クライアント案件の受任/非受任**（営業判断用）
4. **支援プロジェクトの継続/撤退**（運用判断用）

---

## 1. 商品企画の採用/不採用

### 1-1. 採用の絶対条件（これを満たさないと即不採用）

| 条件 | 閾値 | 理由 |
|------|------|------|
| 売場3秒ルール | スコア4以上 | 瞬間訴求できない商品は売場で埋もれる |
| 贈答シーン適合 | 少なくとも1シーンで主役になれる | 「どこにも刺さらない」は売れない |
| 粗利率 | 40%以上 | 販促・流通コストを吸収できない |
| 供給安定性 | 年間12ヶ月供給可能 or 明確な季節限定設計 | 供給不安定はチャネル信頼を失う |
| 日持ち | 販路が要求する最低日持ちをクリア | ミスマッチは命取り |

**一つでも欠けた場合**: 企画を差し戻し、または根本再設計。

### 1-2. 採用推奨条件（揃うと強い）

| 条件 | 内容 |
|------|------|
| 地域象徴性3層 | 原材料・製法・物語の2層以上を満たす |
| 配りやすさ | ピース数・単価がシーンに合致 |
| インバウンド対応 | 英語表記・アレルギー表示の余地がある |
| 季節需要 | 年間の需要の山に乗れる |
| SNS記号性 | 写真・動画で記号化しやすい |

**揃わなくても採用可**。ただし、**ヒット規模は限定的**と想定する。

### 1-3. 即不採用にすべき警告サイン

以下のいずれかがあれば、企画段階で却下:

- **コンセプトが20秒以上の説明を要する**
- **「どこにも刺さる」と言うが、実は誰にも刺さっていない**
- **競合商品との差別化が「より美味しい」だけ**
- **地域性が後付け（原材料・製法・物語のどれにも根拠なし）**
- **担当者の個人的好みに依存した企画**
- **類似商品が既に市場にあり、勝つ根拠がない**

### 1-4. 採用判定フロー（企画会議用）

```
【ステップ1】絶対条件を満たすか
  ├─ No → 即不採用、再設計
  └─ Yes ↓

【ステップ2】即不採用の警告サインがあるか
  ├─ Yes → 不採用、ただし学びを記録
  └─ No ↓

【ステップ3】採用推奨条件の充足数
  ├─ 0〜1個 → 採用保留、強化検討
  ├─ 2〜3個 → 採用、スタンダード投入
  └─ 4個以上 → 採用、主力候補として投入
```

### 1-5. AIで判定する際のプロンプト例

```
以下の商品企画を、採用/不採用判断基準で評価してください。

【企画情報】
[商品名、コンセプト、価格、販路、仕様]

【出力】
1. 絶対条件5項目のチェック結果
2. 警告サイン6項目の該当確認
3. 採用推奨条件5項目の充足数
4. 最終判定（即不採用/採用保留/採用/主力候補）
5. 判定理由（3行以内）
6. 改善すべき点の優先順位
```

## 2. 販路・チャネルの採用/不採用

### 2-1. チャネル採用の判断軸

| 評価項目 | 採用の閾値 |
|---------|---------|
| 目標月間売上に対する販売可能ボリューム | 10%以上 |
| チャネル特性と商品特性の適合 | 70点以上 |
| 先方バイヤーの取引姿勢 | 長期継続視点がある |
| 取引条件（リベート・返品等） | 業界標準の範囲内 |
| 物流コスト | 粗利率を10ポイント以上削らない |
| 競合商品との棚位置 | 埋没リスクが低い |

### 2-2. チャネル撤退の判断基準

以下に該当したら、撤退を検討:

- **連続3期で売上目標の50%未満**
- **粗利率が業界標準を5ポイント以上下回る**
- **返品率が15%を超える**
- **バイヤー・担当者が頻繁に交代し、関係性が築けない**
- **取引条件の一方的な不利益変更が続く**
- **自社ブランドイメージと合わない売場配置が常態化**

### 2-3. 撤退時の手順
1. 社内で撤退決定（経営層承認）
2. バイヤーへの事前告知（3〜6ヶ月前）
3. 既存在庫の処理計画
4. 代替チャネルへのシフト設計
5. 従業員への説明（販売担当のケア）

撤退は「負け」ではなく、**経営判断** である。
続けることで失うリソースの方が大きい場合、速やかに退く。

## 3. クライアント案件の受任/非受任

### 3-1. 受任の絶対条件

| 条件 | 内容 |
|------|------|
| 経営者の本気度 | 経営者自身が月1回以上会議に出る |
| 判断基準を言語化する意思 | ベテランへのヒアリングに時間を割く覚悟がある |
| 現場担当者の配置 | 最低1名の主担当を置く |
| 期間コミット | 最低6ヶ月、推奨1年以上 |
| 投資意思決定のレベル | 月30万円以上の継続投資が可能 |

**一つでも欠けた場合**: **契約を結ばない**。

### 3-2. 即断る条件（受任してはいけない）

- ツールの名前だけ知りたい企業
- 判断基準を言語化する気がない企業
- 結論を先送りしたい企業
- 「AIを入れた実績」だけが欲しい企業
- 業界文化を軽視する経営層
- 当社を「下請け・外注」としてしか見ない企業
- 月額投資額をしきりに値切る企業

### 3-3. グレーゾーン案件の対応

以下のいずれかに該当する場合、**Phase 0（診断）のみを提案**し、本契約は診断結果を見てから判断:

- 経営者の本気度が不透明
- 組織の受容性が読めない
- 期待値が過大（例: 「3ヶ月で売上3倍」）
- 業界理解が極端に浅い

Phase 0の料金だけで30〜50万円程度設定し、互いに判断する時間を作る。

### 3-4. 受任時の合意事項

契約時に、以下を書面で合意:
- 目標とする成果の範囲（コミットできる範囲とできない範囲）
- 双方の責任範囲
- 中途解約条件
- 秘密保持・情報管理
- 成果物の権利帰属
- 事例公開の可否

## 4. 支援プロジェクトの継続/撤退

### 4-1. 成功しているサインと失敗しているサイン

#### 成功している（継続すべき）
- Phase 0〜1で、クライアント側の主担当者が自律的に動き始めている
- 現場から「もっと使いたい」「他の業務にも入れたい」という声が出る
- 経営会議の議題が「AIをどう使うか」から「AIで何を変えるか」にシフトしている
- 導入前の KPI が確実に改善している
- クライアントからの質問の質が上がっている（単純な使い方から戦略論へ）

#### 失敗しているサイン（撤退検討）
- Phase 1終盤でもクライアント側が動かない
- 現場が AI を「余計な仕事」として扱う
- 経営層が現場に丸投げし、自身は関与しない
- 月次レビューにクライアントの主要メンバーが来ない
- 合意していた業務棚卸しが進まない
- 3ヶ月経っても最初のユースケースが稼働しない

### 4-2. 撤退の判断基準

以下のいずれかが2ヶ月以上続いたら、撤退を検討:

- **月次レビューが3回連続で延期**
- **クライアント側の主担当者が実質的に不在**
- **合意事項の履行率が50%未満**
- **経営層のコミットメント低下が明白**
- **当社への支払い遅延が2回以上**

### 4-3. 撤退の進め方

1. **警告フェーズ（1ヶ月目）**: 経営層に問題を共有、改善案を提示
2. **改善フェーズ（2ヶ月目）**: 改善が見られなければ、撤退プランを内示
3. **撤退フェーズ（3ヶ月目）**: 残りプロジェクトの完了 or 打ち切り
4. **終結フェーズ**: 成果物の引き渡し、今後の自走ガイド提供

撤退は相手企業のためでもある。
合わない支援を続けることは、相手のリソースを奪うことと同じ。

## 5. 判断を迷った時の最終問い

### 5-1. 商品企画で迷った時
> 「この商品を、自分なら誰に贈るか?」
> 「3秒で手に取る理由を、自分は本当に持っているか?」

### 5-2. 販路で迷った時
> 「このチャネルで、10年後も貴社のブランドが保てるか?」
> 「短期売上と引き換えに、何を失うか?」

### 5-3. 案件受任で迷った時
> 「この経営者と1年伴走することに、自分はエネルギーを注げるか?」
> 「この案件が成功した時、業界の誰かの役に立つか?」

### 5-4. プロジェクト継続で迷った時
> 「今、撤退した方が、相手のためになるのではないか?」
> 「続けることで、自分の専門性が浅くなっていないか?」

## 6. 判断基準の運用ルール

### 6-1. 判断時にこのファイルを参照
- 企画会議の冒頭にチェックリストを読み上げる
- 新規案件の初回面談後、受任前に照合
- 月次プロジェクトレビューで継続/撤退を判定

### 6-2. 判断実績の記録
- 採用/不採用・継続/撤退の判断実績を蓄積
- 半年ごとに振り返り、判断精度を検証
- 判定後の実績と照合し、基準を微調整

### 6-3. 基準の見直し
- 年1回、判断基準を全面見直し
- 市場変化・事例蓄積に応じて閾値を調整
- 大幅変更時は、正典思想との整合を確認

## 7. この判断基準をAIに実装する

### 7-1. 企画採用判定AI
- 商品企画を入力すると、採用/不採用を判定
- 絶対条件・警告サイン・推奨条件を同時チェック
- 改善案を自動生成

### 7-2. クライアント適性判定AI
- 初回ヒアリングの内容を入力
- 受任すべきか、グレーゾーンか、断るべきかを判定
- 追加確認すべき項目を提示

### 7-3. プロジェクト撤退判定AI
- 月次レビューデータを入力
- 撤退すべきサインがないか自動検知
- 経営層への警告レポートを自動生成
