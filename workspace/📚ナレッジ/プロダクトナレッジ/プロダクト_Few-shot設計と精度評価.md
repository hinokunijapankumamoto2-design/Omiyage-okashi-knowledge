# プロダクトナレッジ: Few-shot設計ルール・精度評価

> **用途**: AIに入れる「例示」と「評価基準」を、業界特化で機能させるための設計方法
> **作成日**: 2026-04-21
> **核心**: Few-shotは量より質。**上位ルール → 例示 → 評価** の順で設計しないと、出力は散る

---

## 0. このナレッジの意図

多くのAI導入失敗は、Few-shot（例示）を「たくさん入れればよい」と誤解するところから始まる。
実際には:

> **Few-shotの質 = 上位ルール（正典・評価軸）の明確さ × 例示の典型性 × 評価フィードバックの継続性**

本ナレッジは、お土産お菓子業界に特化したFew-shotを、**体系的に設計・評価・改善** するための標準手順を提供する。

---

## 1. Few-shot設計の原則

### 1-1. 10項目チェックリスト（Few-shot作成時に必ず照合）

1. **誰向けか** が明確か
2. **何を判断させる文書か** が明確か
3. **入力条件** が網羅されているか
4. **判断基準** が明示されているか
5. **業界特有の軸**（7軸等）が織り込まれているか
6. **AI導入の工程**まで落ちているか
7. **証拠・根拠の出し方** があるか
8. **出力形式** が標準化されているか
9. **反論や失敗リスク** に触れているか
10. **次アクション** が明確か

→ この10項目すべてを満たさないFew-shotは、使ってはいけない。

### 1-2. 上位ルールとFew-shotの関係

```
【Layer 0】正典思想（ブレない思想）
       ↓ 決めるのは人間
【Layer 2】評価軸（7軸等の判断基準）
       ↓ AIに実装する判断ロジック
【Layer 5】Few-shot（例示）
       ↓ AIが学習する具体パターン
【Output】AIが生成する実際の文書
```

**重要**: Few-shotは Layer 0 と Layer 2 に**従属する**。
従属させずにFew-shotを増やすと、例文の寄せ集めになり、判断がブレる。

## 2. Few-shotの構造テンプレート

### 2-1. 基本構造

```markdown
## Few-shot: [文書タイプ名]

### メタ情報
- 対象読者: [経営者/商品企画/営業/販促]
- 判断内容: [この文書で何を決めるか]
- 形式: [報告書/企画書/提案書/議事録]
- 必須業界軸: [7軸のどれに触れるか]
- 次アクション: [この文書の受け手が次に何をするか]

### 入力条件（このFew-shotが想定する状況）
- [条件1]
- [条件2]
- [条件3]

### 判断基準
- [基準1: どう良し悪しを見るか]
- [基準2]
- [基準3]

### 例示
[実際の文書本体]

### 再現ポイント
1. [なぜこの書き方か]
2. [業界文脈のどこに触れているか]
3. [禁忌を避けている場所]

### 出力評価基準
- [このFew-shotに基づく出力が満たすべき条件]
```

### 2-2. このテンプレートの運用
- すべてのFew-shotはこの構造で書く
- 構造が守られていないFew-shotは、AIに渡してはいけない
- 新規追加時は、必ず既存Few-shotとの整合性を確認

## 3. Few-shotの品質階層

### 3-1. 3段階評価

| ランク | 条件 | 利用可否 |
|-------|------|--------|
| S | 実例（実クライアント事例・実投稿）、全10項目充足 | 主力Few-shot |
| A | 生成例、全10項目充足 | 暫定利用可 |
| B | 10項目のうち2個以上欠落 | 改善してから利用 |
| C | 5個以上欠落 or 禁忌リスト該当 | 破棄 |

### 3-2. 品質管理ルール
- S ランクFew-shotが累計10本以上溜まるまで、A ランクを補助的に使う
- 半年ごとにBランクを洗い出し、改善 or 破棄
- Cランクは即廃棄、再利用しない

### 3-3. 現状の品質分布（2026-04時点）
- S: 0本（実サンプル取得待ち）
- A: 4本（コンテンツ_文体パターン集_Few-shot.md内）
- B: 0本
- C: 0本

→ **最優先で S ランクの実サンプル5本を取得する** ことが、AI精度向上への最大投資。

## 4. 業界特化 Few-shot の必須要素

### 4-1. 「お土産お菓子」固有の Few-shot に必ず入れるもの

| 要素 | 入れ方 |
|------|-------|
| 売場情景 | 駅ナカ・空港・観光地・百貨店のいずれかの具体場面 |
| 贈答文脈 | 誰が誰に贈るかのシーン |
| 地域性 | 原材料・製法・物語のいずれかの層 |
| 時間圧 | 帰路直前の2分、お盆の帰省、季節需要等 |
| ベテランの視点 | 業界50年の経験者なら何を見るか |
| 判断の根拠 | 「なぜそう判断したか」の理由付け |

### 4-2. 禁じ手リスト（Few-shotに絶対入れてはいけない）

- 「誰でも簡単」「秒で」「一気に」等の軽薄表現
- 業界への敬意を欠く物言い
- 競合の名指し批判
- 成果の誇張（「売上◯倍保証」等）
- 流行り言葉に依存した説明
- 抽象論だけで情景がない文章

## 6. 精度評価の仕組み

### 6-1. 評価の3つの次元

#### 次元1: 出力の正確性
- 業界用語・地名・商品名が正しいか
- 数値・事実関係に誤りがないか
- 論理展開に破綻がないか

#### 次元2: スタイル適合性
- 正典思想・文体ルールに沿っているか
- 業界文脈が織り込まれているか
- 禁忌リストに該当していないか

#### 次元3: 実用性
- 実務で使える形になっているか
- 受け手が理解できる構造か
- 次アクションが明確か

### 6-2. 評価スコアカード

```markdown
## AI出力評価スコアカード

### 対象
- 生成日: [YYYY-MM-DD]
- 使用Few-shot: [ファイル名]
- 用途: [どこで使うか]

### 次元1: 正確性（20点）
- 用語・地名・商品名の正確性: _/5
- 数値・事実の正確性: _/5
- 論理展開の整合: _/5
- 引用・出典の適切さ: _/5
小計: _/20

### 次元2: スタイル適合性（30点）
- 正典思想との整合: _/10
- 文体ルール遵守: _/10
- 業界文脈の織り込み: _/10
小計: _/30

### 次元3: 実用性（20点）
- 構造の明確さ: _/5
- 実務で使える具体性: _/5
- 受け手への伝わりやすさ: _/5
- 次アクションの明示: _/5
小計: _/20

### 禁忌チェック（減点-20点）
- 禁忌リスト該当: _個 × -5点

### 総合スコア: _/70

### 判定
- 60点以上: そのまま利用可
- 50〜59点: 軽微な修正で利用可
- 40〜49点: 大幅改訂必要
- 39点以下: 破棄・再生成
```

### 6-3. 評価の運用
- 新規Few-shot作成時: スコアカード必須
- 月次の出力サンプル: ランダム10本を評価
- 四半期: 平均スコアの推移を追跡

## 7. 継続的改善ループ

### 7-1. 改善サイクル（PDCA）

```
【Plan】何を改善するか決める
- 月次スコアで低い項目を特定
- 業界トレンドの変化を反映
       ↓
【Do】Few-shotを修正・追加
- 該当Few-shotを改訂
- 必要なら新規追加
       ↓
【Check】出力を評価
- スコアカードで評価
- クライアントのフィードバック収集
       ↓
【Act】標準に反映
- 効果確認後、本番Few-shotに昇格
- 関連ドキュメントにも反映
```

### 7-2. 学習データの蓄積

クライアント導入時に、以下を継続収集:
- 実際のAI出力と、人間が修正した後の出力の差分
- 「使えた/使えなかった」のフィードバック
- 出力を元に取った行動の結果
- 改訂版のFew-shot

これらが蓄積されるほど、精度は複利的に上がる。

### 7-3. 半年ごとの全体見直し
- 全Few-shotを再評価
- 業界動向の変化を反映
- 陳腐化したFew-shotは破棄
- 新しいFew-shotカテゴリの必要性を検討

## 9. AIにFew-shotを渡す時の標準プロンプト

### 9-1. 標準プロンプト構造

```
あなたは、秋坂洋三郎（お土産お菓子研究所-GINZA-代表）として文書を作成します。

【守るべき上位ルール】
1. 正典思想 [参照ファイル]
2. 文体ルール [パーソナルナレッジ6章]
3. 業界評価軸7軸 [参照ファイル]
4. 禁忌リスト [訴求ワード集 + 正典思想 7章]

【参考Few-shot】
以下の例示と、同じ構造・文体・業界文脈で作成してください。
[Few-shot本体]

【依頼内容】
[具体的な依頼: 何を、誰向けに、何のために]

【出力条件】
- Few-shotと同様の構造で
- 業界文脈（売場3秒/贈答/地域性のいずれか）を必ず織り込む
- 禁忌リストに該当しないこと
- 静かな断定型で締める

【自己評価】
出力後、以下を自己チェックしてください:
- 禁忌リスト該当: なし/あり → ある場合は修正
- 業界文脈の織り込み: あり/なし → ない場合は追加
- 正典思想との整合: OK/NG → NGなら再生成
```

### 9-2. この標準プロンプトの意味
- 毎回同じ構造で指示を出すことで、出力の一貫性を担保
- 自己評価を組み込むことで、低品質な出力を削減
- Few-shotと上位ルールを両方渡すことで、学習効果が最大化

## 11. 運用を始める時の最初の一歩

今すぐできる3つのアクション:

1. **既存Few-shotの棚卸し**
   - 現状のFew-shot（文体パターン集内）を10項目チェックに通す
   - ランク判定（現状すべてAランク）
   - 改善すべき項目を特定

2. **実サンプル取得の仕組みづくり**
   - Facebook投稿を書いたら、評価スコアカードをつけて保存
   - 反応の良かった投稿をSランクに昇格
   - 月5本の実例蓄積を目標化

3. **精度評価の習慣化**
   - 月次で、AIに作らせた出力から10本を評価
   - 低スコアの原因をFew-shotにフィードバック
   - 3ヶ月後に平均スコアが10点以上向上していることを目標
