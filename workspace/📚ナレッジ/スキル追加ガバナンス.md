# 🚪 スキル追加ガバナンス

> **確立日**: 2026-04-21
> **位置づけ**: 今後スキルを `~/.claude/skills/` に格納する際の絶対基準
> **背景**: 19スキル監査の結果、52%が機能していないと判明した反省に基づく

---

## 📜 基本原則

> **「追加しない」が最善。追加する場合は5つ全てをクリアする。**

ナレッジベースが育つほど、使われないスキルはノイズになり、**判断の邪魔** になる。
正典思想「変えるべきもの: 情報が散在し再利用できない知識ストック」を、**スキル群にも適用する**。

---

## ✅ スキル追加5チェックリスト

新規スキルを追加する前に、**以下の5つ全てにYesと答えられるか** を確認。

### ✅ チェック1: ビジネスコンテキスト
> そのスキルは、秋坂洋三郎の事業（お土産お菓子×AI）と関連するか?

- ⭕ 「お土産お菓子業界の市場調査レポート生成」
- ❌ 「ブロックチェーン取引分析」
- ❌ 「動画編集プランナー」
- ❌ 「UI/UXレイアウト」（秋坂氏の現業務にない）

### ✅ チェック2: TRIGGER特異性
> description に、固有のキーワード・概念が含まれているか?

- ⭕ 「SCQA」「Excalidraw」「KENGOOD」「Anthropic SDK」
- ❌ 「ライティング」「要約」「生成」（汎用すぎる）
- ❌ 「コンテンツ転用」「構造化」（業務との紐付けなし）

**強化形**: description に `TRIGGER when: ...` と `SKIP: ...` を明示する。

### ✅ チェック3: ネイティブツール非代替性
> Write / Edit / TodoWrite / WebSearch / Bash で代替できないか?

- ⭕ 「Excalidraw専用JSONフォーマット生成」（ネイティブでは作れない）
- ❌ 「ワークフロー分解」（TodoWriteで代替）
- ❌ 「文章要約」（標準プロンプトで代替）
- ❌ 「ブランドトーン統一」（パーソナルナレッジ参照で代替）

### ✅ チェック4: 既存ナレッジ非重複
> ナレッジ文書（📚ナレッジ配下）で既に表現されていないか?

- ⭕ 新しい技術（未文書化の新機能）のスキル化
- ❌ 「訴求ワード生成」（訴求ワード集.md がある）
- ❌ 「競合分析」（競合分析.md がある）
- ❌ 「文体統一」（パーソナルナレッジ 6章がある）

### ✅ チェック5: 他スキル非重複
> 既存スキル（standard + custom）と機能が被っていないか?

- ⭕ 明確に違う領域
- ❌ `infographic-builder` vs `excalidraw-diagram-generator`（重複）
- ❌ `hook-generator` vs `structured-copywriting-skill`（重複）
- ❌ `tone-style-enforcer` vs `コンテンツ_文体パターン集`（重複）

## 🚦 判定フロー

```
新規スキル追加の検討
        ↓
  【チェック1】ビジネス関連? → No → 【追加しない】
        ↓ Yes
  【チェック2】TRIGGER特異? → No → description強化 or 【追加しない】
        ↓ Yes
  【チェック3】ネイティブ代替不可? → No → 【追加しない】
        ↓ Yes
  【チェック4】ナレッジ重複なし? → No → ナレッジで完結 【追加しない】
        ↓ Yes
  【チェック5】他スキル重複なし? → No → 統合 or 【追加しない】
        ↓ Yes
  【追加OK】~/.claude/skills/ に格納
        ↓
  3ヶ月後: 発動実績チェック
        ↓
  発動ゼロなら削除検討
```

## 📋 追加時の必須記載事項

新規スキルファイル `SKILL.md` には、以下を全て含める:

```yaml
---
name: [スキル名]
description: [一行で何をするか]
TRIGGER when: [発動する具体条件1; 条件2; 条件3]
SKIP: [発動しない条件1; 条件2]
license: ...
---

# [スキル名]

## なぜこのスキルが必要か
[他の手段では代替不可能である根拠]

## 関連ナレッジ
- [参照するナレッジファイル]

## 業務での使用場面
- [秋坂氏の業務フローのどこで使うか]

## Overview
[概要]

## Features
[機能]

## Output Format
[出力形式]

## Instructions
[指示]

## Constraints
[制約]

## 3ヶ月後の評価予定
[発動実績を測定する基準]
```

## 🕰️ 定期メンテナンス

### 四半期ごと（3ヶ月に1回）
- 全スキルの発動実績を確認
- 3ヶ月間発動ゼロのスキルは削除検討
- 新しく必要になったスキルを追加検討

### 半期ごと（6ヶ月に1回）
- 全スキルの description を正典思想と照合
- ビジネスフェーズの変化に応じた統廃合
- ナレッジファイルとの整合性再確認

### 年次
- 全スキルを5チェックリストで再監査
- 使われていないスキルの完全削除
- ガバナンスルール自体の見直し

## 🎓 過去の失敗から学んだこと

### 失敗1: 一括導入（2026-04-21）
20スキルを一度に追加 → 監査で52%が機能しないと判明。
**教訓**: 1スキルずつ厳選して追加する。一括は避ける。

### 失敗2: 汎用的なdescription
「ライティング」「要約」のような一般語ではClaudeが発動しない。
**教訓**: 固有キーワードを必ず含める。

### 失敗3: ネイティブツールとの重複
`workflow-automation-agent` は `TodoWrite` と完全に機能が重複していた。
**教訓**: まずネイティブツールで実現できないか検討する。

### 失敗4: ナレッジとの重複
文書で表現できることをスキル化しても、どちらも参照されない。
**教訓**: スキルは「発動トリガー」、ナレッジは「参照情報」と役割を分ける。
