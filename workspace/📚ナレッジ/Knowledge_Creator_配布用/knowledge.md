# Knowledge（ナレッジ自動振り分け）

## 概要

雑多に投げられた情報を受け取り、最適なナレッジファイルに自動で振り分け・追記・新規作成する。
「Knowledge」や「/knowledge」と入力するだけで、あとはAIが判断して最適な場所に格納する。

## 実行フロー

### Step 1: 入力情報の分析

ユーザーから受け取った情報を分析し、以下を判定:
- **情報の種類**: パーソナル情報/プロダクト情報/コンテンツソース/リサーチデータ/その他
- **既存ナレッジとの関連**: 追記すべきファイルがあるか/新規作成すべきか

### Step 2: フォルダ構造の確認

ナレッジフォルダの構造を確認:

```
📚ナレッジ/
├── パーソナルナレッジ/
├── プロダクトナレッジ/
└── コンテンツナレッジ/
```

1. Globでフォルダ内のファイル名を一覧取得
2. 既存ファイルの中から、入力情報に該当するものを検索
3. 該当ファイルがあれば内容を読み込んで追記位置を特定

### Step 3: 振り分け判定

| 情報の種類 | 保存先 | アクション |
|---|---|---|
| 自分の実績・プロフィール更新 | パーソナルナレッジ | 既存に追記 |
| 商品情報の変更・追加 | プロダクトナレッジ | 既存に追記 |
| コンテンツの文字起こし・テキスト | コンテンツナレッジ | 既存に追記 or 新規作成 |
| リサーチ結果・データ | 適切なフォルダ | 新規作成 or 既存に追記 |
| その他の情報 | ナレッジフォルダ直下 | 新規作成 |

### Step 4: 実行

**既存ファイルに追記する場合:**
1. 既存ファイルを読み込み
2. 追記位置を特定（セクション見出し等で判断）
3. 構造を維持したまま情報を追記
4. 更新日を記載

**新規ファイルを作成する場合:**
1. ファイル名を決定（内容がわかる名前）
2. 適切なフォルダに配置
3. 構造化されたMarkdownで作成
4. 作成日を記載

### Step 5: 報告

```
▶ ナレッジを更新しました。

[追記 or 新規作成] → [ファイルパス]
内容: [追加した情報の要約（1〜2行）]
```

## 文字起こしテキストの品質補正

文字起こしデータが含まれる場合は自動補正:
1. 前後文脈による誤字修正
2. 既存ナレッジとの照合（固有名詞・専門用語の表記統一）
3. フィラー除去（口癖として有用なものは残す）
4. 修正箇所の明示

## 重要ルール

- **既存ファイルへの追記を優先。** 不必要に新規ファイルを増やさない
- **追記前に既存ファイルの内容を必ず確認。** 重複する情報を入れない
- **ファイルの構造を壊さない。** 既存のセクション構成を維持したまま追記
- **保存先を必ず報告。** ユーザーがどこに保存されたか把握できるように
- **迷ったらユーザーに確認。** 「この情報は [ファイル名] に追記しますか？ それとも新規作成しますか？」
