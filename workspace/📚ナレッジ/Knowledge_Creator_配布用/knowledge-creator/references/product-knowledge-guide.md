# プロダクトナレッジ構築 完全ガイド v1.1

## 目的
商品・サービスの情報を体系的に構造化し、セールスLP・セミナー台本・配信文のすべてで一貫したメッセージングを実現する基盤を作る。

## 全体構成
**17項目 × 5フェーズ**で全項目を埋める。

| フェーズ | 項目数 | 内容 |
|---|---|---|
| Phase 1: 商品概要 + コンセプト | 5項目 | 商品名、コンセプト、USP、カリキュラム、サポート |
| Phase 2: オファー + 訴求 | 3項目 | 特典、料金、訴求キーワード |
| Phase 3: ターゲット情報 | 5項目 | 属性、悩み、理想、恐怖、マインドセット |
| Phase 4: 実績 | 2項目 | 商品実績、クライアント事例 |
| Phase 5: ファネル + 特典詳細 | 2項目 | ファネルマップ、特典詳細 |

## 対話フロー詳細

### Phase 1: 商品概要 + コンセプト（5項目）
**ヒアリング内容:**
1. **商品概要**: 商品名・商品形態・価格・提供方法・一言説明
2. **コアコンセプト**: 核となるメッセージ1〜3文（「一言で言うと何を提供するのか」）
3. **USP**: 競合にない強み3つ（「なぜ他ではなくこの商品を選ぶべきか」）
4. **カリキュラム構成**: 月別orステップ別の提供内容
5. **サポート体制/コミュニティ**: どんなサポートがあるか（チャット、添削、コミュニティ等）

**Deep Dive ポイント:**
- コンセプトは「他との違い」が明確かどうか確認
- USPが「みんな言ってること」になっていないか厳しくチェック
- 「それは他の商品でも言えることですか？」で独自性を追求

**確認・要約:** 構造化して提示→「OK」で次へ

### Phase 2: オファー + 訴求（3項目）
**ヒアリング内容:**
6. **入会特典一覧**: 各特典の内容・数量・制作コスト
7. **料金プラン/保証制度**: 一括/分割、保証の有無と条件
8. **訴求キーワード一覧**: セールスコピーで使う刺さるワード10個以上

**Deep Dive ポイント:**
- 特典は「何が含まれるか」だけでなく「なぜそれが価値あるか」まで聞く
- 訴求キーワードは実際に反応が良かったものを優先

**確認・要約:** 構造化して提示→「OK」で次へ

### Phase 3: ターゲット情報（5項目）
**ヒアリング内容:**
9. **ターゲット属性**: 職業・年齢・状況・理解レベル（AI/マーケ等のリテラシー）
10. **ターゲットの悩み/課題**: トップ5（表面的な悩み + 本質的な悩み）
11. **理想の未来**: 手に入れたいもの（短期 + 長期）
12. **避けたい未来**: 恐怖・不安（短期 + 長期）
13. **必須マインドセット**: 求める受講者像（「こういう人に来てほしい/来てほしくない」）

**Deep Dive ポイント:**
- 悩みは「表面」と「本質」を分離（例: 表面=「集客できない」、本質=「自分に自信がない」）
- 理想の未来は「感情」まで聞く（「月収100万」ではなく「家族に感謝される自分」等）

**確認・要約:** 構造化して提示→「OK」で次へ

### Phase 4: 実績（2項目）
**ヒアリング内容:**
14. **商品/サービス実績**: 数値ベース（受講者数、売上、満足度、継続率等）
15. **クライアント成果事例**: ビフォアフ+期間+数値、最低3名

**Deep Dive ポイント:**
- 事例は「Before→After→感情→期間」の4要素が揃っているか確認
- 数字が曖昧なら具体化を求める

**確認・要約:** 構造化して提示→「OK」で次へ

### Phase 5: ファネル + 特典詳細（2項目）
**ヒアリング内容:**
16. **ファネルマップ**: 認知→興味→信頼構築→教育→オファー→購入→継続
    - 各ステージの媒体、見込み客の状態、ゴール、KPIを記入
17. **リストイン特典 + セミナー特典**: 詳細内容、コピー一覧

**Deep Dive ポイント:**
- ファネルの「弱いステージ」を特定して補足ヒアリング
- 特典のコピーは「実際に使っている文言」をそのまま収集

**確認・要約:** 構造化して提示→「OK」で次へ

### 完了チェック
全17項目の情報充足を確認。不足あれば追加ヒアリング。

### 統合ナレッジ出力
`output-templates.md` のプロダクトナレッジテンプレートに従い出力。

## 商品がまだない/設計中のユーザーへの対応
- 競合商品の分析をサポート（「参考にしたい商品のURLやLPはありますか？」）
- 最低限「誰の」「何の悩みを」「どう解決するか」の3要素を言語化
- 「まだ決まっていない項目は仮置きで入れて、後で `/knowledge` で更新できます」と案内
