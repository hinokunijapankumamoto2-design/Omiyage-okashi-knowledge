# コンテンツナレッジ（発信ソースナレッジ）構築ガイド v1.1

## 目的
ユーザーの過去コンテンツから再利用可能な「成功法則」と「設計図」を抽出し、AIが再現可能なナレッジを構築する。

## 最重要目標
**このナレッジを読んだ別セッションのAIが、オリジナルと見分けがつかないレベルで再現できる精度。**

## 核心原則：「骨組み」×「具体」の二層抽出

### 第1層：骨組み（Skeleton）
- コンテンツの構造・展開フロー・各パートの役割を完全に分解
- 「何を」「どの順番で」「なぜその順番で」伝えているかを明確化
- 各パートの意図・目的・心理効果を言語化

### 第2層：具体（Flesh）
- 骨組みの各パートに対応する実際の文章サンプルを紐付け
- オリジナルからの引用を添える
- 再現可能なサンプルを提供

## ソースカテゴリ（12カテゴリ）

本体の12カテゴリに完全準拠:

| # | カテゴリ | 対応するソース |
|---|---|---|
| 1 | 発信ジャンルの人気ワード + 共通言語 | ジャンル全体からAIが抽出 |
| 2 | 発信ターゲット情報 | ヒアリング or コンテンツから推論 |
| 3 | セミナー/個別相談 | セミナー台本、資料テキスト、文字起こし |
| 4 | YouTube | 横動画台本、ショート台本、概要欄テンプレ |
| 5 | X | ポスト文章、X動画 |
| 6 | Instagram | リール台本、フィード台本、ストーリー台本、LIVE文字起こし |
| 7 | Threads | 投稿文章 |
| 8 | note / ブログ | 記事文章 |
| 9 | メルマガ / LINE | 配信文テキスト |
| 10 | LP | オプトインLP、誘導LP、決済LP |
| 11 | 自社会員コンテンツ | カリキュラム、動画講義、コミュニティLIVE |
| 12 | その他 | Voicy、Podcast、書籍等 |

## テキスト取得方法

### API自動取得（推奨）
- **YouTube Data API**: 動画タイトル、概要欄、字幕データを一括取得
- **X API**: 過去の投稿テキスト、エンゲージメントデータを取得
- **Zoom API / Plaud**: 録画の文字起こしを自動取得

### 手動取得
- テキストを直接コピー&ペースト
- スクリーンショットからのテキスト抽出
- 台本ファイルの直接読み込み

### 競合コンテンツの分析
- 参考にしたいアカウントのURLを共有してもらう
- 公開コンテンツを分析対象にする（著作権に注意：参考にはOK、丸パクリはNG）
- 自分のコンテンツが少ないユーザーには積極的に提案

## 分析項目（必須）

### 文体・口調分析
- **文末表現パターン**: 断定系/問いかけ系/共感系/行動喚起系の出現比率（%）
- **一人称・二人称**: 使用パターンと使い分けルール
- **口癖・言い回し**: 最低10個、使用シーン付き
- **感情表現**: 熱量の上げ方/共感の示し方/危機感の煽り方/安心感の与え方
- **文章リズム**: 一文の長さ/改行頻度/強調の仕方

### Few-shot Examples（必須4パート）
1. **導入パート**: シーン + オリジナル抜粋 + 再現ポイント3つ以上
2. **教育パート**: シーン + オリジナル抜粋 + 再現ポイント3つ以上
3. **共感パート**: シーン + オリジナル抜粋 + 再現ポイント3つ以上
4. **クロージング・CTA**: シーン + オリジナル抜粋 + 再現ポイント3つ以上

## 文字起こしの品質補正
文字起こしデータを受け取ったら即座に補正:
1. **前後文脈による誤字修正**: 音声認識の誤変換を文脈から推定して修正
2. **既存ナレッジとの照合**: ユーザーのナレッジファイル内の固有名詞・専門用語と照合
3. **フィラー除去**: 「えーと」「あのー」等を除去、ただし口癖として有用なものは残す
4. **修正箇所の明示**: `[修正: 元→修正後]` の形で一覧提示して確認

## 出力品質の自己チェック
- [ ] 別AIが再現できるレベルか
- [ ] 文末表現が数値化されているか
- [ ] 口癖が10個以上あるか
- [ ] Few-shotが4パート以上あるか
- [ ] 「骨組み」と「具体」が全フェーズにあるか
- [ ] 引用量が30%以上あるか
- [ ] プレースホルダー（仮置き文字）が残っていないか
