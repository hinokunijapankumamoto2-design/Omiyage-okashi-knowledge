## 🎯 このナレッジベースは何か

### 一言で
**お土産お菓子メーカー専用の「判断基盤」を構築するためのAI学習データ基盤。**

### 誰のためのものか
- **秋坂洋三郎**: 日々の発信・提案・セールスの一次情報として
- **協業パートナー**: 組織の共通言語として
- **AI（Claude等）**: 「秋坂洋三郎として書く」際の参照元として
- **将来のスタッフ**: 組織の思想と方法論を学ぶ教科書として

### 何ができるようになるか
このナレッジを参照したAIは、以下が可能になります:

- 秋坂洋三郎の文体・思想・判断で発信文を生成
- お土産菓子特化7軸で商品企画を評価
- 競合3群と明確に差別化されたセールス資料を作成
- クライアント企業の業務をAI組織化して提案
- Phase 0〜3の90日導入ロードマップを具体化

## 📏 AI出力の品質チェックリスト

発信・公開前に、必ず以下を確認:

### ✅ Level 1: USP整合性
- [ ] 「商品開発コンサル」に見えていないか
- [ ] 「汎用AI支援」に見えていないか
- [ ] 「判断基盤」「意思決定構造」「属人知の資産化」のいずれかに言及

### ✅ Level 2: 文体
- [ ] 「誰でも簡単」「秒で」「今すぐ」等の禁止表現なし
- [ ] 軽薄なAI論に堕していない
- [ ] 情景→構造→業界文脈→静かな結論 の流れ

### ✅ Level 3: 業界文脈
- [ ] 売場3秒ルール
- [ ] 贈答シーン
- [ ] 地域性3層
- [ ] 季節・動線

上記4つのいずれかに触れている

### ✅ Level 4: 差別化
- [ ] 「ブランド会社ではここまで、AI会社ではここまで、私どもはこう」構造
- [ ] 競合を名指しで批判していない

### ✅ Level 5: 成果の語り方
- [ ] 時間削減の数値
- [ ] 生産量増加の倍率
- [ ] 判断精度向上の指標
- [ ] 過剰約束（◯倍保証等）になっていない

## 🔄 更新・追加のルール

### 情報を追加したい時
**方法A（推奨）**: `/knowledge` コマンドで自動振り分け
```
/knowledge [追加したい情報]
```
→ AIが最適な保存先を判断して追記

**方法B**: 該当ファイルに直接追記
- 各ファイル内の「更新ルール」セクションを参照
- 更新日を記載して履歴を残す

**方法C**: 新規区分が必要な場合
- 新しいサブフォルダを作成
- `ナレッジ索引.md` に追加
- この README を更新

### バージョン管理
各ファイルの更新は以下で記録:
- 変更日
- 変更内容（簡潔に）
- バージョン番号（必要な場合）

## 🎓 思想の核（ここだけは絶対）

### お土産菓子の定義
> お土産菓子は、甘い食品ではない。
> **旅の終わりに置かれ、人と人の距離を縮め、地域の魅力を持ち帰らせる「道具」である。**

### AIの定義
> AIは効率化ツールではない。
> **人間の認知負荷を再配分する装置**である。
> **職人の勘を組織の知能に変える**仕組みである。

### 我々の使命
> 日本のお菓子文化を、未来へつなぐ。
> その手段として、**地方老舗の意思決定構造をAIで再生させる。**

### 絶対に守るもの
- 地域文化と職人の誇り
- 味と技術の伝承
- 贈答文化の文脈
- 業界への敬意
- 現場の尊厳

### 積極的に変えるもの
- 鈍くて重い定型業務
- 属人化した判断構造
- 時代遅れの売り方
- ベテラン不在時に機能停止する脆い組織
- 情報が散在し再利用できない知識ストック
