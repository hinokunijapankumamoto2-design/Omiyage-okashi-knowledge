# 覚醒モード（Awakening）

複雑なタスクの実作業前に実行する 6 ステップの覚醒手順。
最後に「覚醒ブリーフィング」を提示してから実作業に入る。

発動しない条件: 目的と完了条件が明確で、低リスクかつ局所的であり、
複数段階の調査・設計・外部連携を必要としない単純なタスク。直接実行する。
判定が微妙な場合は **失敗コストと不可逆性** を基準にし、高ければ発動する。

---

## 覚醒手順（6ステップ）

### Step 1: 目的と完了条件の言語化

- このタスクの目的を 1〜2 文で言語化する
- 「何ができたら完了か」を検証可能な形で定義する
- 目的や完了条件が曖昧なままなら、推測で進めずユーザーに質問する

### Step 2: コンテキスト装填（KENGOOD統合）

- **反省ノート**: `mistakes.md` を読み込み、今回のタスクに適用される過去のミスルールを列挙する
  - 探索順: プロジェクトの `.claude/rules/mistakes.md` → Vault ルート（`~/.claude/knowledge-config.json` の `vault_path` を参照）
  - 見つからなければ「反省ノートなし」としてスキップ（エラーにしない）
- **第2の脳**: Vault がある場合は `wiki/INDEX.md` を確認し、タスクに関連するトピックを実作業に持ち込む
- プロジェクトの CLAUDE.md・既存コード・既存ドキュメントのうち、影響範囲にあるものを確認する

### Step 3: 前提の検証

- 重要な前提を列挙し、「確認済みの事実」と「未確認の推測」に分類する
- 不明点を事実のように扱わない。ツールで検証できるものはこの場で検証する
- 検証できない前提は、ブリーフィングに前提として明記する

### Step 4: リスク・盲点・代替案

- 失敗した場合のコストと不可逆性を評価する
- 盲点、リスク、機会、反対意見、代替案を必要な範囲で示す
- **不可逆な操作**（削除・上書き・外部送信・公開・本番反映）が含まれるかをここで判定する
  → 含まれる場合、このタスクは「リスク高」として扱う（実行ゲートに影響）

### Step 5: 実行計画と検証計画

- 「今やること」と「今はやらないこと」を分けて明示する
- 複数段階のタスクは手順に分解する（大規模ならプランモードの使用を検討）
- **検証計画**: 完了をどう確かめるか（テスト・実行確認・照合方法）を実作業前に定義する
- 助言だけで終わらせない。安全かつ権限内で、実務成果物と検証まで進める計画にする

### Step 6: リソース設定の監査

- **思考深度**: 難しい設計判断・デバッグには拡張思考を深く使う。機械的な作業には使わない
- **サブエージェント**: 独立した調査・作業が複数並列できる場合のみ検討。トークン消費が大きいため、並列化の効果が見込める時に限る
- **モデル**: 変更はユーザーの明示的な依頼と検証可能な根拠がある場合のみ（勝手に変えない）

## 覚醒ブリーフィング（出力フォーマット）

覚醒手順の完了後、実作業に入る前に以下を提示する。各項目 1〜3 行、長くしない。

```
## 覚醒ブリーフィング

- **目的**: [1〜2文]
- **完了条件**: [検証可能な形で]
- **適用ルール**: [mistakes.md から該当するもの。なければ「該当なし」]
- **関連ナレッジ**: [wiki から持ち込むトピック。なければ「該当なし」]
- **前提**: [確認済み / 未確認を区別して]
- **リスク**: [失敗コスト・不可逆性・盲点]
- **今やること**: [手順]
- **今はやらないこと**: [スコープ外の明示]
- **検証方法**: [完了をどう確かめるか]
- **リソース**: [思考深度・サブエージェント要否]
```

## 実行ゲート

ブリーフィング提示後の動きは、Step 4 のリスク判定で分岐する:

- **リスク高**（不可逆な操作を含む / 失敗コストが大きい）:
  ブリーフィングを提示して **ユーザーの承認を待ってから** 実行する
- **それ以外**: ブリーフィング提示後、**そのまま実行に移る**（承認を待たない）

## 品質基準（実作業中も維持）

- 結論を先に示し、事実・根拠・論理を優先する
- 「最適解」を保証せず、利用可能な情報・権限・時間の範囲で最も根拠の強い解を目指す
- タスク完了時、ミスがあれば反省ノートのルール化 3 条件に照らして `mistakes.md` への追記を検討する

## 優先順位

ユーザーの明示的な指示、適用されるプロジェクト固有の指示（プロジェクトのCLAUDE.md）を本スキルより優先する。
