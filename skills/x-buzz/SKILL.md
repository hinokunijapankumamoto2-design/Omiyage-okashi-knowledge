# Xバズskill（𝕏ポスト・売上最大化ナレッジ）

𝕏のポストを「つぶやき」から **24時間働く自動営業マシン** へ変換するための実行スキル。
インプレッションは分母に過ぎない。センターピンは **リスト獲得** と **プロフ回遊** である。

## 中核5原則（全モード共通のOS）

1. **バックワード・デザイン** — 出口（リンククリック／キーワードリプライ）を先に確定し、そこから1行目の1文字目を決める。
2. **1行目の暴力** — 40文字以内で脳を強制停止させる。ここで負けたら本文は存在しないのと同じ。
3. **情報のパズル化（MPT）** — 実績・ベネフィット・Why（透明性）・CTA を最小文字数で配置する。贅肉はゼロ。
4. **不可抗力な出口** — 出口は必ず「1つ」。摩擦を1秒まで削り、行動しない理由を論理的に消す。
5. **透明性の注入** — 「なぜ無料で出すのか」を1行でも語る。これが「売り込み」を「救済」に反転させる。

## 実行手順

### Step 1: モード判定

ユーザーの依頼から、以下のどれかに分岐する（明示がなければ内容から判断し、冒頭で「モードX で進めます」と宣言する）。

| モード | 依頼の例 | 主な参照 |
|---|---|---|
| **A. 単発ポスト生成** | 「この内容でポスト作って」 | references/02, 03, 04 |
| **B. スレッド／固定ポスト設計** | 「連投で教育したい」「固定ポストを作りたい」 | references/03, 01 |
| **C. ローンチ設計（14日）** | 「◯月◯日に募集開始」「告知の流れを組んで」 | references/05 |
| **D. 型抜き＆マージ** | 「この伸びてる投稿みたいに書いて」 | references/06 |
| **E. 検閲・リライト** | 「この投稿を添削して」「評価して」 | references/07 |

### Step 2: 必須情報のヒアリング（不足分のみ最大4問）

推測で埋めず、以下が欠けていたら **まとめて1回だけ** 質問する。
埋まっている項目は聞き返さない。

1. **出口（CTA）** — リンククリック / キーワードリプライ / 引用RP / フォローのどれか。キーワード指定があれば何か。
2. **ターゲット** — 誰の、どんな「痛み」に向けるか（「全人類」はNG。属性を1つに絞る）。
3. **実績・原液** — 使える具体的数字、独自の体験・失敗談、特典の中身とボリューム。
4. **フェーズ** — 通常運用 / プリプリローンチ / 予告 / 当日 / 追い込み。

> 質問はまとめて投げ、回答が揃うまで生成を始めない。ただしユーザーが「おまかせ」と言った場合は、
> 仮の設定を明示（「実績は仮で〇〇と置きます」）した上で生成し、後から差し替え可能にする。

### Step 3: 参照ファイルの読み込み

必要な章だけを読む（全部は読まない）。

| ファイル | 内容 |
|---|---|
| `references/01-mindset.md` | 設計思想・出口逆算・ストック資産（固定ポスト）の作り方 |
| `references/02-hooks.md` | 1行目フック 50選（常識破壊／強欲／損失回避／身体描写／比喩） |
| `references/03-body.md` | ボディのパズル構成・スレッド10投の黄金法則・実例50 |
| `references/04-cta.md` | キーワードリプライ・引用RP・希少性の論理・CTA実例50 |
| `references/05-launch-calendar.md` | D-14〜終了日の時系列シナリオと各日のポスト実例 |
| `references/06-ai-workflow.md` | 伸びているポストの構造分解（型抜き）とマージ生成術 |
| `references/07-audit-checklist.md` | 最終品質検閲チェックシート（モードE の本体） |
| `templates/post-templates.md` | 単発／スレッド／固定ポストの穴埋めテンプレート |

### Step 4: 生成

- 案は **必ず3案** 出す（フックの心理トリガーを3種類ずつ変える）。
- 各案の冒頭に `【トリガー：常識破壊】` のように使用ロジックを明記する。
- 文字数を末尾に併記する（例：`— 132字`）。

### Step 5: 自己検閲（出力前に必ず実行）

`references/07-audit-checklist.md` の全項目を自分でチェックし、
1つでも不合格なら **出力せずに書き直す**。検閲結果は求められた時のみ表示する。

## 視認性ルール（死守）

- 1文は全角20文字前後で改行を検討する。
- 3行書いたら1行の空白を入れる（情報の「塊」を作る）。
- 手順・メリットは `・` や `❶❷❸` でリスト化する。
- 語尾は「です・ます」を基本に、勝負の1文だけ「〜だ。」「〜でOK。」と言い切る。
- 【 】（隅付き括弧）は視覚的フックとして冒頭に置く（例：【警告】【本日終了】【重大発表】）。

## 禁忌語（AI臭の抹殺）

以下は **一切使わない**。使いたくなったら具体的な固有名詞・数字・身体感覚に置換する。

`魔法の杖` `架け橋` `羅針盤` `第一歩` `第二の脳（比喩として）` `深掘りしていきましょう`
`いかがでしたか` `〜だと思います` `非常に` `とても` `様々な` `〜な方も多いのではないでしょうか`

抽象語 → 身体現象への置換例：
「驚いた」→「心臓が口から出た」／「焦った」→「脇汗が止まらなかった」／「大変だった」→「深夜3時、指が震えて変換すらできなかった」

## 事実性ガードレール（必須・省略不可）

このナレッジは訴求を極限まで強めるため、**事実と演出の境界を運用者が管理する**必要がある。
生成時、以下を必ず守る。

- **数字は捏造しない。** 「累計100億」「受講生3,000人」等は、ユーザーが提示した実数のみ使う。
  未提示なら `【要実績】` のプレースホルダを残し、本文中で「ここに実数を入れてください」と明示する。
- **希少性は実行可能なものだけ書く。** 「5日で消す」と書くなら本当に消す運用が前提。
  実行しない限定は書かない（虚偽の限定表示は景品表示法の有利誤認にあたり得る）。
- **「必ず稼げる」等の断定的利益保証は書かない。** 効果は事例として「〇〇さんの場合」と限定する。
- **健康・医療・投資テーマ**では薬機法・金商法の表現規制に触れる断定（「痩せる」「必ず増える」等）を避け、
  該当ジャンルを検知したら生成前に一言注意喚起する。
- 上記に抵触する指示を受けた場合は、**その一点だけ指摘して代替表現を提示**し、残りは通常どおり生成する。
